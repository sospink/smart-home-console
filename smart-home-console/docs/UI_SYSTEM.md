# UI、动效与素材方案

米家官方多端控制产品的调研证据、可转译原则及版权边界见 `docs/MIJIA_UI_RESEARCH.md`。

## 管理端表单表面规则

- 层级固定为画布、工作面板、分组行、可编辑控件；分组行与控件必须有可辨认的表面差，不叠加两套常驻描边。
- 输入框、数字框与 Select 默认以背景层级表达边界，hover/focus 才显示状态轮廓；不得用 `overflow: hidden` 裁掉聚焦环。
- 分页项目与尺寸选择器统一 44px 触控高度；分页容器允许换行，并在面板右侧保留至少 24px 聚焦安全空间。
- 浅色和深色主题均需检查编辑行、折叠编辑器、文本域、分页尺寸选择器和下拉浮层。

## 视觉命题

“安静、克制的住宅控制界面”：浅色以暖白画布与白色圆角表面为材料，深色以中性近黑画布和递进灰卡片为材料，两者都只使用一条米家蓝表达选中、实时状态和主操作。项目原创、离线打包的家居空间插画负责空间氛围。主屏为“场景影像 + 设备卡片画廊 + 聚焦控制器”；副屏为“一眼状态 + 场景快捷带 + 单设备聚焦控制”；工程端为“同主题导航 + 工程工作台”。

## 内容计划

### 主屏 1920×1080

1. 顶部居中系统身份、时间、环境和实时连接；
2. 左侧首页/场景/设备/安防/环境/能耗/设置导航；
3. 场景页使用四张影像卡，以生活语义直接执行场景；
4. 设备页使用房间筛选和四列设备卡片画廊，卡片直接呈现状态与开关，右侧是单对象聚焦控制器；
5. 右侧对场景执行和设备能力进行即时控制；
6. 命令 pending/confirmed/failed 反馈和紧急告警。

### 副屏 1024×600

1. 顶部展示空间、环境、网关和全屋关灯；
2. 四个高频场景构成连续快捷带；
3. 灯光、窗帘、音乐使用类型切换和单设备聚焦控制，不并排堆叠控制卡；
4. 灯光支持亮度、色温与电源，窗帘支持位置和开停关，音乐支持音量和电源；
5. 窗帘聚焦页使用状态驱动的落地窗空间控制器：帘布宽度、中央开口和采光随确认位置变化，底部连续刻度与开/停/关形成独立控制坞；1424×280 隐去空间造型但保留全部关键操作；
6. 右侧汇总安防、门窗、网关和最高优先级告警；
7. 1424×280 下折叠摘要区，保留场景、设备类型和当前聚焦控制。

### 管理端

1. Naive UI 提供表单、选择、开关、折叠、空状态和输入校验；
2. 页面跟随全局浅色/深色主题，Naive UI 表单、弹层与工作表面使用同一主题状态，同时保持工程信息密度；
3. 房间设备、场景、联动、告警、网关、终端、备份和审计共用一套密度与状态语言；
4. `/admin` 使用路由级动态加载，主副屏不加载 Naive UI 后台代码。

## 交互命题

只保留三类有业务意义的动效：

1. **命令确认**：点击后按钮/Toast 进入 pending，设备确认后变为 confirmed；失败显示原因；
2. **场景执行轨迹**：进度线按实际已确认动作增长，不用无意义循环光效；
3. **共享状态转场**：主屏操作经 WebSocket 使副屏数字和状态平滑变化，强调两屏来自同一权威状态源。

持续旋转只用于等待；呼吸光只用于在线/活动。系统顶栏提供“完整/精简/关闭”三档动效，偏好在同源主屏、副屏和后台间同步并持久化；未明确选择时遵循 `prefers-reduced-motion`，关闭档同时禁止触控涟漪。

所有终端顶栏都提供操作回执中心，从 EdgeCore 权威快照汇总最近设备命令、场景执行与告警，显示发起端、时间、确认/失败状态和失败原因；角标只表示当前进行中操作与未解决告警，不把历史失败永久计数。

动效候选、技术选型、性能边界和实施优先级详见 `docs/MOTION_IDEAS.md`。推荐主题为“设备有生命、命令有能量流、场景有执行轨迹、双屏有同步反馈”。

## 设计令牌

| 角色    | 值        | 语义                   |
| ------- | --------- | ---------------------- |
| Canvas  | `#F5F6F7` | 主背景                 |
| Surface | `#FFFFFF` | 控制表面               |
| Text    | `#191B1E` | 主文字                 |
| Muted   | `#85898F` | 次级信息               |
| Blue    | `#32AAFF` | 选中、实时状态、主操作 |
| Gold    | `#F4A340` | 注意、部分完成状态     |
| Violet  | `#8178F5` | 辅助数据层级           |
| Green   | `#18C891` | 成功、健康             |
| Danger  | `#FF5D72` | 告警、失败、离线       |

深色主题使用 `#101113` 画布、`#151619` 顶栏/侧栏、`#1C1D20` 一级卡片和 `#24262A` 二级控制块；主文字 `#F3F4F5`、次文字 `#A4A7AC`。深色不使用大面积藏蓝、发光边框或纯黑卡片，蓝色仍只用于选中与操作。主题按钮位于所有终端的系统顶栏，选择存入本机显示偏好并在同源主屏、副屏和后台间即时同步。

圆角 10/14/20；独立主表面可使用 22–24px，设备卡使用 18px。主要触控按钮在工控屏上保持有效触控区至少 44×44 CSS px。

## 组件规则

- 卡片只用于独立可操作对象；导航、数据表、场景列表优先使用分区、线和留白；
- 顶栏、侧栏、面板标题和连续列表不以贯穿式描边分割；优先使用画布/表面明度、12–24px 间距和圆角分组。仅滑杆、窗帘轨道、进度、表单焦点与危险状态保留有业务语义的线；
- 选中态使用浅蓝填充、图标色和轻微抬升，不使用左侧竖线或整圈高对比描边；主模块切换即时完成，不做会产生白屏、旧页残留或页面叠加的布局转场；
- 告警颜色不能只靠颜色表达，必须带图标和文字；
- 设备能力从 API 返回，页面不应给不支持的设备显示控制项；
- 门锁只读时不出现开锁按钮；
- 主屏首页设备按收藏优先、排序补足显示；后台可设置收藏、排序和隐藏，但传感器与门锁必须保持可见，前端和 EdgeCore 都执行校验；
- 加载、空、离线、部分成功、失败均有独立状态；
- 副屏不允许出现横向滚动或依赖 hover 的关键操作。
- Naive UI 只用于工程后台和复杂通用交互，主副屏的场景画布、设备造型和大触控面保持自研。

## 素材库

- 图标：Lucide（ISC），构建时打包；
- 场景卡片：`src/assets/scenes` 下回家、离家、观影、夜间四张原创离线 SVG，来源登记见 manifest；
- 实物设备图：到货后自行拍摄和去底；
- 场景照片：如确有需要，使用可证明授权的自有摄影或生成素材，并转 WebP；
- 禁止电商图片、米家截图和小米 Logo 未经许可进入商业产品。

素材登记见 `src/assets/ASSET_MANIFEST.md`。

## 视觉验收

- 主屏视口：1920×1080，另测合同最低 1920×720；
- 副屏视口：当前采购 1024×600；另建立合同 1424×280 适配断点，但不能把软件适配当成硬件参数合格；
- Android WebView 测试：字体、SVG、WebSocket、CSS Grid、range 触控、全屏、24h 内存；
- Android 壳层可通过 `smart-lab:screen-saver` 自定义事件的 `detail.active` 主动开启/关闭屏保，接近事件沿用 `smart-lab:proximity`；
- 所有主操作 1 米观察可辨，7 寸副屏触控靶不小于 44px；
- 录制场景执行和跨屏同步，动效不得影响操作响应。
- Playwright 额外截取主屏各模块、后台登录和 9 个正式工程页，输出至 `output/playwright/*-redesign.png`。
- 主题回归必须覆盖：浅色→深色→刷新持久化→副屏切回浅色→主屏/副屏/后台同步，以及两套主题下的目标视口无溢出。
