# 米家控制端 UI 调研与项目转译

调研时间：2026-07-22，2026-07-23 复核。目标是在不使用小米商标、官方截图和专有素材的前提下，高保真转译官方公开界面的产品组织、尺度、层级和主题语言。

## 官方证据

### 米家官网

[米家官方首页](https://home.mi.com/)明确说明：

- 米家覆盖手机、平板、家庭智能屏等多端，并强调多端一致；
- 灯光、窗帘、环境、摄像机按高频品类自动归纳；
- 支持一键关灯和一屏查看多个监控；
- 自动化以回家、离家、环境变化等生活语义组织。

官网公开的多端产品图显示，平板/家庭屏采用浅灰画布、白色圆角设备卡、浅层房间或品类导航、少量重点对象和较大的单设备控制面。平板横屏会并排显示多张设备卡，手机端则以双列卡片组织；两者都把设备状态直接放在卡片中。

### Xiaomi 智能家庭屏 11

[官方产品页](https://www.mi.com/xiaomi-smartdisplay-11)说明：

- 首页快捷控制覆盖照明、环境、插座开关、监控、窗帘和家务类设备；
- 支持查询设备工作状态、耗材与模式，但能力取决于设备实际是否上报；
- 支持场景、监控联动、动态屏保和大字模式；
- 产品本身为封闭应用生态，不能把它当成可安装本项目 APK 的通用安卓平板。

### 小米 IoT 开发者平台

[小米 IoT 开发者平台](https://iot.mi.com/)是产品接入、能力定义与开发管理入口，不是面向住户的家庭控制大屏。项目管理后台可以借鉴其“工作台 + 表单/列表”的信息架构，但不应把开发者控制台样式搬到主副控制屏。

## 可转译的设计原则

1. **房间与高频品类优先**：用户首先选择空间或灯光/窗帘/音乐，不先面对所有设备矩阵。
2. **单对象聚焦控制**：选中对象后展示一个连续的大控制面，数值、滑杆、预设和主开关在同一区域。
3. **场景是生活动作**：回家、离家、观影、夜间使用横向快捷带，不做同权重卡片墙。
4. **状态靠近动作**：控制旁显示实时状态、确认来源和异常，避免另开一套监控面板。
5. **高频全局动作可直接到达**：例如全屋关灯、一键场景和最高优先级告警。
6. **能力门禁**：只有实际设备上报的属性才显示；不绘制虚假环境趋势和能耗曲线。
7. **多端一致、密度不同**：主屏承担空间浏览与详情，副屏承担高频聚焦控制，后台承担配置；三端共享状态和视觉语言，但不能是同一个布局缩放。
8. **常用对象可个性化**：本项目将首页收藏、隐藏和排序交给工程后台持久化；与家庭 App 自助编排不同，实训环境同时强制门锁与传感器保持可见，优先满足教学安全和验收可观测性。

## 本项目视觉方向

保留“知境”自有身份，从工业蓝监控大屏转向米家公开界面所体现的住宅控制产品：

- 暖白/浅灰画布、白色控制表面、近黑正文和单一湖蓝主操作；绿色只表达成功/在线，暖色只表达灯光或注意状态；
- 图片、设备本体和大数值承担视觉重心；
- 设备页恢复官方平板式设备卡片画廊，因为卡片本身就是选择、状态和开关的交互对象；不使用纵向工程表格；
- 主屏为“场景影像 + 设备卡片画廊 + 聚焦控制器”，副屏为“高频聚焦控制台”，后台为同主题的浅色工程工作台；
- 14–24px 圆角由表面层级决定：设备卡 18px、主表面 20–22px、胶囊动作 16–18px。

## 明确不采用

- 不声称存在或复刻了未公开的“米家 Web 家庭控制台”；
- 不使用米家 Logo、官方图标、电商截图或产品宣传图作为交付素材；
- 不把非交互数据做成无意义的卡片墙；设备卡片因承载选择、状态与开关而保留；
- 不以橙色或绿色换肤冒充米家设计；
- 不把 IoT 开发者后台的信息架构直接用于住户控制屏。

## 深色主题延伸

米家 App Store 官方截图以明亮家庭空间为主，并在 3D 中控等沉浸式空间使用近黑背景。项目深色主题据此做体系化延伸，而不是声称复制某一张未公开的米家深色规范：采用 `#101113` 画布、`#1C1D20` 一级卡片和 `#24262A` 二级控制块，禁用大面积藏蓝与发光描边；米家蓝只用于选中、开关和关键状态。浅色与深色共享布局、圆角、密度和语义色，避免切换主题时改变操作结构。
